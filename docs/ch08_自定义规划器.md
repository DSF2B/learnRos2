## 8.1 学习目标

- 理解 ROS 2 的插件机制（pluginlib）及其解决的问题
- 掌握"继承接口 → 注册 → 动态加载"的完整流程
- 实现一个直线全局规划器，替换 Nav2 默认的 NavFn 规划器

## 8.2 插件机制：不改框架代码，换掉核心算法

假如你想在 Nav2 里试验自己的路径规划算法，而 Nav2 是别人写好的框架——**框架怎么知道你的算法存在？** 这就是 pluginlib 解决的问题：

1. **约定接口**：Nav2 定义抽象基类 `nav2_core::GlobalPlanner`（5 个虚函数），并承诺"我只调用接口，不管你内部实现"
2. **你实现插件**：继承该接口，实现 `createPlan` 等函数
3. **运行时按名字加载**：Nav2 配置文件里写 `planner_plugin_ids: ["ch8_custom_planner::StraightLinePlanner"]`，pluginlib 找到这个名字对应的 .so，加载、实例化、调用

这就是经典的**策略模式（Strategy Pattern）框架化**——Nav2 的全局规划器、局部规划器（控制器）、代价地图层、行为树节点全部是插件。ROS 2 生态里 pluginlib 无处不在：控制器（ch6 的 diff_drive_controller）、RViz2 面板、slam_toolbox 求解器……

## 8.3 插件注册五步走

**① 继承接口**（straight_line_planner.hpp）：实现 5 个虚函数——`configure`（初始化，拿到 logger/TF/代价地图）、`activate`/`deactivate`/`cleanup`（生命周期，教学插件空实现）、`createPlan`（核心）。

**② 实现**（straight_line_planner.cpp）：直线插值——距离 / 0.05m 的密度生成路径点：

```cpp
int n = std::max(1, static_cast<int>(dist / 0.05));
for (int i = 0; i <= n; ++i) {
  pose.pose.position.x = start.pose.position.x + dx * i / n;
  ...
}
```

**③ 注册宏**（cpp 文件末尾）：

```cpp
PLUGINLIB_EXPORT_CLASS(ch8_custom_planner::StraightLinePlanner, nav2_core::GlobalPlanner)
```

**④ 插件清单**（plugins.xml）：library path 是 .so 名去掉 lib 前缀和 .so 后缀，type 是完整类名，base_class_type 是接口类名——pluginlib 运行时靠这三者对上号。

**⑤ 声明导出**：package.xml 的 `<nav2_core plugin="${prefix}/plugins.xml"/>` + CMake 的 `pluginlib_export_plugin_description_file(nav2_core plugins.xml)`（写进 ament 索引）+ 安装 .so、头文件、xml。

**验证插件被找到**：

```bash
ros2 component types | grep -i planner   # 列出现有组件
# 更直接：查 ament 索引里注册的插件
cat install/ch8_custom_planner/share/ament_index/resource_index/nav2_core__pluginlib__plugin | grep straight
```

## 8.4 使用：把默认规划器换成自己的

Nav2 的参数文件（默认 `/opt/ros/humble/share/nav2_bringup/params/nav2_params.yaml`）里改两处：

```yaml
planner_server:
  ros__parameters:
    # 换成我们注册的插件类名（原值 NavFn 对应类名 nav2_navfn_planner/NavfnPlanner）
    planner_plugin_ids: ["ch8_custom_planner::StraightLinePlanner"]

# 如果带上了自定义参数节，框架会按插件名传递
```

```bash
ros2 launch nav2_bringup bringup_launch.py \
  params_file:=/path/to/my_nav2_params.yaml map:=/path/to/map.yaml
```

然后 RViz2 发目标点：路径会是一条**笔直的线**（撞墙也直走——因为它不做避障）。对比默认 NavFn 的绕障路径，插件机制一目了然。

> 注：`planner_plugin_ids` 支持列表——可以同时加载多个规划器，按名字选择。

## 8.5 设计要点：从教学插件到真实算法

直线规划器只有教学意义，真实规划器要处理三件事，思考它们能帮你理解 Nav2 内部：

1. **代价地图**：`configure` 拿到的 `costmap_ros_` 是障碍物的栅格表示——真实算法（A*、Dijkstra、RRT）都在它上面搜索。试试调用 `costmap_ros_->getCostmap()` 读代价。
2. **坐标系**：起点/终点通常在不同 frame（map/odom），需要 TF 变换到同一系再插值——`tf_` 就是为此提供的。
3. **起点替换**：全局规划通常以"机器人当前位姿"为起点而不是请求里的 start（更平滑）。

## 8.7 常见坑

1. **报 "According to the loaded plugin descriptions the class xxx does not exist"**——插件类名与 plugins.xml 不一致；或没重新 source install/setup.bash（ament 索引是 install 后生成的）；或 .so 没装到 lib 目录。
2. **加载成功但 configure 崩溃**——`node_.lock()` 返回空：Nav2 传入的是生命周期节点的 weak_ptr，节点被销毁后插件就失效，先判空。
3. **改了插件代码行为不变**——没有重新 `colcon build` + source；插件是动态库，Nav2 启动时加载的是 install 里的 .so。
4. **头文件找不到**——忘了 `target_include_directories` + `install(DIRECTORY include/)`，其他包 include 你的头文件会失败。
5. **路径发布到错误坐标系**——createPlan 的 header.frame_id 与 start 一致（本插件已处理），否则 RViz2 里路径画到天边。

## 3.2 话题通信模型

话题是 ROS 2 中**最常用**的通信方式，适合持续、单向、多对多的数据流（传感器数据、速度指令）：

```
  发布者 A ──┐
  发布者 B ──┼──► [话题 topic] ──┬──► 订阅者 X
                              ├──► 订阅者 Y
                              └──► 订阅者 Z
```

三个关键性质：

1. **匿名与解耦**：发布者和订阅者互不知道对方存在，通过 DDS 自动发现。谁先启动都行。
2. **多对多**：一个话题可以有多个发布者和多个订阅者。
3. **异步**：发布者发出消息立即返回，订阅者的回调何时执行由执行器决定。

> 延伸：每个话题上流动的消息**类型**是固定的（如 `std_msgs/msg/String`）。如果发布者和订阅者消息类型不一致，DDS 会发现但拒绝配对，表现为"收不到消息"且不报错——这是新手第一大坑。

## 3.3 基础发布/订阅：talker / listener

`talker.cpp` 的核心三步：

```cpp
// ① 创建发布者：模板参数是消息类型，参数是话题名和队列深度
publisher_ = this->create_publisher<std_msgs::msg::String>("chatter", 10);

// ② 组装消息
auto msg = std_msgs::msg::String();
msg.data = "Hello ROS2 topic";

// ③ 发布
publisher_->publish(msg);
```

`listener.cpp` 的核心一步：

```cpp
subscription_ = this->create_subscription<std_msgs::msg::String>(
  "chatter", 10,                                  // 话题名 + 队列深度
  std::bind(&Listener::topic_callback, this, _1)); // 收到消息时调用成员函数
```

回调签名注意：`const std_msgs::msg::String::SharedPtr msg`——**消息以共享指针传入**，ROS 2 官方建议不要修改它（如需修改，显式拷贝一份）。队列深度 10 表示订阅者来不及处理时最多缓存 10 条，再多的消息按 QoS 策略丢弃。

## 3.4 自定义消息：ch3_interfaces + Weather

`std_msgs` 只提供基本类型，真实项目需要自定义消息表达业务数据。自定义接口的固定套路：

**Step 1：创建接口专用包**（约定：接口独立成包，业务包依赖它）

```bash
cd cpp/src
ros2 pkg create ch3_interfaces --build-type ament_cmake --dependencies rosidl_default_generators
rm -rf ch3_interfaces/src ch3_interfaces/include   # 接口包不需要这些目录
mkdir ch3_interfaces/msg
```

**Step 2：写 .msg 文件**（msg/Weather.msg）——字段格式：`类型 名称`，类型只支持内置类型（`float64`、`string` 等）或其他消息类型：

```
float64 temperature
float64 humidity
string  condition
```

**Step 3：package.xml 三件套 + CMake 生成**

```xml
<build_depend>rosidl_default_generators</build_depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>
```

```cmake
rosidl_generate_interfaces(${PROJECT_NAME} "msg/Weather.msg")
```

**Step 4：业务包使用**——依赖加 `ch3_interfaces`，代码里 include 生成的头文件：

```cpp
#include "ch3_interfaces/msg/weather.hpp"      // 文件名是消息名转小写 snake_case
auto msg = ch3_interfaces::msg::Weather();     // 命名空间: 包名::msg::消息名
msg.temperature = 25.5;
```

生成的头文件在 `install/ch3_interfaces/include/` 下，可以打开看生成代码长什么样。

## 3.5 实战：海龟画圆（闭环控制）

`turtle_circle.cpp` 是本教程第一个**带反馈的控制器**，结构值得仔细体会：

```
            ┌─────────────── turtle_circle 节点 ───────────────┐
            │                                                 │
 期望半径 ──►│ P控制器：w = v/R + kp·(r - R)  ──cmd_vel──► 海龟  │
            │          ▲                          │          │
            │          └────────── pose ◄─────────┘          │
            └─────────────────────────────────────────────────┘
```

**开环 vs 闭环**：开环做法是"直接发一个固定的 v 和 w"，海龟会画圆——但速度受系统负载影响，圆的大小不可控。闭环做法**把位姿读回来**，与目标比较得到误差，再修正输出：

```cpp
double error = radius - r;                  // 半径误差
cmd.angular.z = v / radius + kp * error;    // 稳态项 + P 修正项
```

- `v / radius` 是理论角速度（圆周运动：w = v / R）
- `kp * error` 是比例修正：实际半径偏小 → 减小 w → 转弯变缓 → 半径变大

这就是 PID 中的 **P（比例）控制**，ch9 会完整展开。尝试把 kp 调大/调小，观察振荡与收敛速度的变化。

## 3.7 常见坑

1. **消息类型不匹配**：订阅者"静默收不到消息"。用 `ros2 topic info <话题>` 对比两端的 Type，或看 `ros2 doctor` 提示。
2. **话题名拼写不一致**：`/turtle1/cmd_vel` 与 `turtle1/cmd_vel` 在 ROS 2 中等价（首斜杠可省略），但 `turtle1/cmd_vel` 和 `cmd_vel` 是两个不同的话题！乌龟程序都带 `/turtle1/` 前缀。
3. **改了 .msg 文件后其他包报找不到类型**：先编译接口包，再编译依赖它的业务包（colcon 会处理顺序，但必须一次编译两者）。
4. **回调里做耗时操作**：回调阻塞会导致队列积压、消息延迟。耗时任务应放独立线程或改成 service/action（ch4/ch5）。
5. **`ros2 topic pub` 发一次就退出了**：加 `--times 10` 指定次数或 `--rate 1` 持续发送；消息内容格式用 `ros2 interface show <类型>` 查看字段。

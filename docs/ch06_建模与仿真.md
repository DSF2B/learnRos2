## 6.2 URDF：用 XML 描述机器人

URDF（Unified Robot Description Format）用 **link（连杆）+ joint（关节）** 描述机器人的机械结构：

- **link**：刚体，有 visual（显示用）、collision（碰撞用）、inertial（惯性：质量 + 惯性张量，物理仿真必需）
- **joint**：两个 link 的连接，6 种类型——`fixed`（固定）、`revolute`（旋转，有限角度）、`continuous`（旋转，无限，轮子用它）、`prismatic`（直线）等

joint 的核心是 `<origin>`（子相对父的位置/姿态）和 `<axis>`（旋转轴）。写 URDF 的关键是**把每个 link 的局部坐标系想清楚**：小车的 base_link 原点在车体几何中心，左轮装在 `(+0.12, 0, 0)`，右轮 `(-0.12, 0, 0)`。

> URDF 只有结构，不含代码。它通过 `robot_description` 参数在节点间传递（见 ch5 的 TF 思路），RViz2 / Gazebo 都从这个参数读取模型。

## 6.3 Xacro：让 URDF 可编程

纯 URDF 写真实机器人会陷入大量复制粘贴：左右轮结构一样却要写两遍，改个轮子半径要全文替换。Xacro 是 URDF 的模板语言，三大件：

```xml
<!-- ① property：常量 -->
<xacro:property name="wheel_radius" value="0.035"/>

<!-- ② macro：带参数的代码块（注意宏内用 ${} 引用参数） -->
<xacro:macro name="wheel" params="prefix x_reflect">
  <link name="${prefix}_wheel">...</link>
</xacro:macro>

<!-- ③ 调用：左右轮各一行 -->
<xacro:wheel prefix="left" x_reflect="1"/>
<xacro:wheel prefix="right" x_reflect="-1"/>
```

`${}` 里可以做表达式运算（`${base_height/2 + wheel_radius}`），`${pi}` 是内置常量。Xacro 文件由 `xacro` 命令展开成纯 URDF：

```bash
ros2 run xacro xacro src/ch6_robot/urdf/robot.xacro   # 直接看展开结果
```

**robot.xacro 结构**：常量区 → 惯性/轮子宏 → 车身 → 左右轮 → 万向轮 → 激光雷达/IMU/深度相机 → ros2_control 配置。

## 6.4 传感器插件：模型长出"眼睛"

URDF 只能描述机械结构，传感器靠 Gazebo 的 `<gazebo>` 标签注入（book 重点：激光雷达、IMU、深度相机）：

```xml
<gazebo reference="lidar_link">
  <sensor type="ray" name="lidar">
    <ray>...</ray>                              <!-- 扫描范围、分辨率 -->
    <plugin filename="libgazebo_ros_ray_sensor.so">   <!-- Gazebo 插件 -->
      <ros><namespace>/mini_car</namespace>
           <remapping>~/out:=scan</remapping></ros>   <!-- 发布到 /mini_car/scan -->
      <output_type>sensor_msgs/LaserScan</output_type>
      <frame_name>lidar_link</frame_name>             <!-- 数据的坐标系 -->
    </plugin>
  </sensor>
</gazebo>
```

| 传感器 | sensor type | 插件库 | 输出话题（本模型） |
|--------|-------------|--------|------------------|
| 激光雷达 | `ray` | libgazebo_ros_ray_sensor.so | /mini_car/scan |
| IMU | `imu` | libgazebo_ros_imu_sensor.so | /mini_car/imu |
| 深度相机 | `depth` | libgazebo_ros_camera.so | image_raw / depth/image_raw / points |

注意传感器话题都挂了 `/mini_car` 命名空间——多机器人时避免话题冲突的标准做法。

## 6.5 ros2_control：让 cmd_vel 驱动轮子

仿真里轮子是物理实体，谁来把速度指令变成轮子转动？ros2_control 是 ROS 2 官方的机器人控制框架，分工如下：

```
cmd_vel ──► diff_drive_controller（解算左右轮速度）
                │
                ▼
        controller_manager（管理控制器生命周期）
                │
                ▼
   GazeboSystem 硬件接口（把速度写入仿真）
```

三个组成部分：

1. **URDF 里的声明**（robot.xacro 末尾）：
   - `<ros2_control>` 声明哪些关节暴露 `velocity` 命令接口（控制器只写这些接口，不直接碰仿真）
   - `<transmission>` 声明电机到关节的传动关系
   - `<gazebo><plugin>` 加载 `libgazebo_ros2_control.so`，指向控制器配置
2. **控制器配置**（config/diff_drive.yaml）：`diff_drive_controller` 的参数——轮距 0.24、轮半径 0.035，控制器据此解算差速运动学并输出里程计
3. **launch 里的 spawner**：把控制器加载进 controller_manager

> 为什么绕这一大圈？**复用**：同一份控制器代码（diff_drive_controller 是官方库），硬件层换成真电机就是真车（ch9 就是这个思路），换成 Gazebo 就是仿真车。控制器代码与硬件无关。

## 6.6 运行

```bash
source /opt/ros/humble/setup.bash
cd cpp && colcon build --packages-select ch6_robot && source install/setup.bash

# ① 只看模型（RViz2：Add → RobotModel，Fixed Frame 选 base_link）
ros2 launch ch6_robot display.launch.py
ros2 run rviz2 rviz2

# ② 完整仿真
ros2 launch ch6_robot gazebo.launch.py

# ③ 控制小车（仿真跑起来后，新终端）
ros2 topic pub /diff_drive_controller/cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.3}, angular: {z: 0.5}}" --rate 10
# 观察：ros2 topic echo /diff_drive_controller/odom
```

## 6.7 常见坑

1. **Gazebo 里机器人不动**——多半是控制器没加载成功：看 gazebo.launch.py 终端里 spawner 的输出；`ros2 control list_controllers` 检查 `diff_drive_controller` 是否 `active`。
2. **RViz2 里模型散架/错位**——TF 树断（Fixed Frame 选错）或 joint 的 origin 写错，用 `ros2 run tf2_tools view_frames` 检查 TF 树。
3. **时间不同步**——仿真里所有节点都要 `use_sim_time: True`（本项目的 gazebo.launch.py 已配置），否则数据时间戳对不上，TF/传感器数据看起来"卡住"。
4. **改 xacro 后没效果**——xacro 是运行时展开的，改了要重启 launch；如果改了包名/目录，还要重新 `colcon build`（install 目录里才是运行时文件）。
5. **URDF 检查工具**：`check_urdf`（结构）、`urdf_to_graphiz`（画 link/joint 图），在 ROS 1 里常用，ROS 2 可用 `ros2 run xacro xacro` 看展开结果排查语法。

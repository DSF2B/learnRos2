## 5.2 TF：机器人系统的"空间枢纽"

### 为什么需要 TF

机器人身上的传感器各说各话：激光雷达测的是**雷达坐标系**下的距离，摄像头输出的是**相机坐标系**下的像素。要把障碍物标记到**地图坐标系**里，就需要知道各个坐标系之间的相对关系。TF 做的就是这件事——维护一棵**坐标系树**，任何节点都可以查询任意两个坐标系之间的变换。

```
world ──► base_link ──► lidar
   └────► rotor        └──► camera
```

规则只有两条：**每棵树只有一个根**（上图的 world）、**每个坐标系只能有一个父坐标系**（但可以有多个子）。

### 发布变换（dynamic_tf_broadcaster.cpp）

TF 变换本质是发到 `/tf` 话题上的 `TransformStamped` 消息，只是换了个 API：

```cpp
geometry_msgs::msg::TransformStamped t;
t.header.frame_id = "world";     // 父
t.child_frame_id = "rotor";      // 子
t.transform.translation.x = 1.0; // 平移
tf2::Quaternion q; q.setRPY(0, 0, angle);   // 旋转（欧拉角 -> 四元数）
broadcaster_->sendTransform(t);  // 发布
```

- **静态变换**（static_tf_broadcaster.cpp）：父子关系永远不变（如 base_link → lidar 的安装位姿），发一次即可，走 `/tf_static` 话题，TF 内部会缓存
- **动态变换**（dynamic_tf_broadcaster.cpp）：关系随时间变化（如 odom → base_link），按频率持续发布（通常 10~100Hz）

> 四元数为什么不用欧拉角？欧拉角有万向锁问题（俯仰 ±90° 时丢失一个自由度），且插值不平滑。TF 内部一律用四元数，`setRPY` / `getEulerYPR` 负责换算。

### 监听变换（tf_listener.cpp）

```cpp
tf_buffer_ = std::make_shared<tf2_ros::Buffer>(this->get_clock());      // 缓存 TF 数据
tf_listener_ = std::make_shared<tf2_ros::TransformListener>(*tf_buffer_); // 订阅 /tf

auto t = tf_buffer_->lookupTransform("world", "rotor", tf2::TimePointZero);
```

- `TimePointZero` 表示"给我最新可用的"
- 查不到会抛 `tf2::TransformException`，**必须 try-catch**（坐标系不存在、数据未到达、时间戳超出缓存都会抛）
- 时间戳不对是 TF 最经典的坑：机器人上所有节点必须用**同一个时间源**（仿真时间或同一时钟），否则查询不到对应时刻的变换

### 命令行验证

```bash
ros2 run tf2_ros tf2_echo world rotor      # 持续打印两个坐标系的关系
ros2 run tf2_tools view_frames             # 生成坐标系树 PDF（frames.pdf）
ros2 topic echo /tf                        # TF 底层就是普通话题
```

## 5.3 rqt：图形化的"调试控制台"

rqt 是插件化工具集，都用 `ros2 run rqt_xxx xxx` 启动（需图形界面）：

| 工具 | 用途 | 配合本章程序 |
|------|------|-------------|
| `rqt_graph` | 看节点-话题关系图，**排查"谁在发、谁在听"的首选** | 同时跑 talker/listener，看到 chatter 连线 |
| `rqt_console` | 集中看所有节点的日志，按级别过滤 | 跑 turtle_circle，看 INFO/WARN |
| `rqt_topic` | 图形化 echo 话题 | 监听 chatter |
| `rqt_plot` | 把话题里的数值画成实时曲线 | 画 `/turtle1/pose/x` |
| `rqt_reconfigure` | 图形化调参（需节点支持动态参数描述） | 配合 ch4 参数 |

典型排查流程：**现象不对 → rqt_graph 看拓扑 → rqt_console 看日志 → rqt_topic/plot 看数据**。

## 5.4 RViz2：可视化一切

RViz2 是机器人"上帝视角"：显示 TF 坐标系、激光点云、相机图像、路径规划结果。启动：

```bash
ros2 run rviz2 rviz2
```

实操（配合本章 TF 程序）：

1. 启动 static_tf_broadcaster 和 dynamic_tf_broadcaster
2. RViz2 里把 **Fixed Frame** 改成 `world`
3. Add → By display type → **TF**，即可看到 base_link 和匀速旋转的 rotor 坐标系
4. 尝试把 Fixed Frame 改成 `rotor`，观察整个世界开始"旋转"——**固定参考系决定了你看世界的位置**

> 使用技巧：RViz2 配置可以 File → Save Config As 保存成 .rviz 文件，之后 `ros2 run rviz2 rviz2 -d <配置文件>` 直接加载（ch6 会用到）。

## 5.5 ros2 bag：把话题数据"录下来"

bag 是 ROS 的话题录制格式，用途：**离线调试**（复现一次现场）、**数据采集**（录下传感器数据做算法开发）、**回归测试**。

```bash
# 录制（配合 talker 运行）
ros2 bag record -o my_bag /chatter          # -o 指定输出目录前缀
# Ctrl+C 停止

ros2 bag info my_bag                        # 查看录制了哪些话题、多少条、时长

# 回放（另起终端，listener 会收到历史消息）
ros2 bag play my_bag
```

注意：回放时消息时间戳还是录制时刻的。如果节点用 TF 做时间对齐，回放需要配合 `--clock`（让 bag 发布 /clock 模拟时钟），并给节点设置 `use_sim_time` 参数（ch6 仿真会正式用到）。

## 5.7 常见坑

1. **lookupTransform 抛异常不处理导致崩溃**——TF 查询失败是常态（节点启动顺序、时间戳差异），必须 catch。
2. **RViz2 报 "No tf data"**——Fixed Frame 填了不存在的坐标系，或 TF 发布节点没启动。
3. **静态变换节点退出了**——静态变换发布到 `/tf_static`（latched），节点退出不影响已发布的变换；但如果重启系统，所有节点都要重新启动。
4. **bag 回放数据"对不上"**——录制和回放的 QoS 必须兼容；带 TF 的系统回放要配 `--clock` + `use_sim_time`。
5. **rqt_graph 里节点在但线断了**——话题名或消息类型不一致（回到 ch3 坑1）。

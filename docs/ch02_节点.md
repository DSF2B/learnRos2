# 第2章 ROS 2 基础入门——从第一个节点开始

> 对应《ROS 2机器人开发：从入门到实践》第2章

## 2.1 学习目标

- 理解节点（Node）在 ROS 2 中的地位：一切功能都以节点的形式存在
- 掌握功能包（package）的结构与创建方法
- 掌握 workspace 的组织方式与 colcon 编译流程
- 用**面向对象**的方式设计节点（继承 `rclcpp::Node`）

## 2.2 节点：机器人系统的"细胞"

一个机器人的软件系统由几十个节点组成：相机节点、雷达节点、定位节点、底盘控制节点……每个节点**只做一件事**，节点之间通过话题/服务通信（ch3/ch4）。这种设计的好处：

- **解耦**：某个节点崩溃不影响其他节点
- **分布式**：节点可以运行在不同机器上
- **可复用**：功能独立的节点可被不同机器人复用

一个节点的生命周期：`rclcpp::init()` 初始化 → 创建 Node → 执行器 spin 处理回调 → `shutdown()` 销毁。**节点本身不干活，它只是通信的入口；真正的逻辑写在回调函数里，由执行器（executor）驱动**。

## 2.3 功能包与 workspace

### 包的结构（以 ch2_node 为例）

```
ch2_node/
├── package.xml        # 包清单：名字、版本、依赖（必须）
├── CMakeLists.txt     # 编译规则（ament_cmake 构建类型的包必须有）
├── LICENSE
└── src/
    ├── ch2_node.cpp       # 过程式写法
    └── ch2_oop_node.cpp   # 面向对象写法（本章新增）
```

`package.xml` 中的关键字段：

```xml
<depend>rclcpp</depend>              <!-- 编译+运行都需要的依赖 -->
<buildtool_depend>ament_cmake</buildtool_depend>  <!-- 构建工具 -->
```

### workspace 最佳实践

```
cpp/                  # workspace 根
├── src/              # 只放源码包（自己写的包都在这里）
├── build/            # colcon 的中间产物（可删）
├── install/          # 编译安装结果（可删）
└── log/              # 编译日志（可删）
```

三个生成目录里都有 `COLCON_IGNORE` 文件，防止 colcon 把它们误当源码扫描。**永远只编辑 src/ 下的内容**，删掉 build/install/log 后重新 colcon build 可以解决大部分"编译报莫名错误"的问题。

### 从零创建一个包

```bash
cd cpp/src
ros2 pkg create --build-type ament_cmake --dependencies rclcpp my_first_pkg
# 会生成 my_first_pkg/ 骨架（package.xml + CMakeLists.txt + src/）
# Python 包则用 --build-type ament_python
```

ch2_pkg 就是这样创建出来的第一个包（ROS 2 官方教程命名习惯也叫 `my_first_pkg`）。

## 2.4 代码解析

### 2.4.1 过程式写法：ch2_node.cpp

```cpp
rclcpp::init(argc, argv);                 // 1. 初始化 ROS2 上下文（必须先于一切）
auto node = std::make_shared<rclcpp::Node>("cpp_node");  // 2. 创建节点
RCLCPP_INFO(node->get_logger(), "hello cpp node");       // 3. 输出日志
rclcpp::spin(node);                       // 4. 进入事件循环，处理回调
rclcpp::shutdown();                       // 5. 善后清理
```

五步就是所有 ROS 2 C++ 程序的骨架。注意 `spin` 会**阻塞**直到节点被 Ctrl+C 终止——只要还有回调要处理，程序就不能退出。

### 2.4.2 面向对象写法：ch2_oop_node.cpp

真实的机器人项目里，过程式写法会被抛弃，因为：

- 节点的功能复杂后，全局变量/自由函数会失控
- 回调函数需要访问节点状态，OOP 让"状态"成为成员变量

核心模式是**继承 + 成员回调**：

```cpp
class OopNode : public rclcpp::Node
{
public:
  explicit OopNode(const rclcpp::NodeOptions & options = rclcpp::NodeOptions())
  : Node("oop_node", options)      // ① 基类构造函数完成节点初始化
  {
    this->declare_parameter<std::string>("greeting", "Hello");  // ② 声明参数
    timer_ = this->create_wall_timer(500ms, [this]() { this->timer_callback(); });  // ③ 定时器
  }

private:
  void timer_callback() { ... }     // ④ 成员函数作回调，可访问所有成员
  rclcpp::TimerBase::SharedPtr timer_;
  int count_{0};
};
```

四个要点：

1. **初始化在基类构造函数**：`Node("oop_node", options)` 里完成了注册、参数服务等一切工作，派生类构造函数只需要"接线"（声明参数、创建定时器/订阅）
2. **回调绑定成员函数**：`create_wall_timer` 接受 `std::function`，lambda 捕获 `this` 是 rclcpp 中最常见的模式
3. **句柄用 SharedPtr 管理**：timer/subscription/publisher 的生命周期由智能指针接管，节点析构时自动释放
4. **参数即配置**：`declare_parameter` 声明默认值，运行时可改

### 2.4.3 用到的 C++ 特性

| 特性 | 用途 |
|------|------|
| 智能指针 `std::make_shared` | 节点和句柄的内存管理，rclcpp 全 API 都用它 |
| `auto` | 推断 `rclcpp::TimerBase::SharedPtr` 等冗长类型 |
| lambda 捕获 `[this]` | 把成员函数变成 `std::function` 回调 |
| 成员初始化列表 `count_{0}` | 与构造函数 `Node(...)` 区分开，避免"节点没初始化就用到成员" |
| `using namespace std::chrono_literals` | 写 `500ms` 这样的时间字面量 |

## 2.5 编译与运行

```bash
source /opt/ros/humble/setup.bash
cd cpp
colcon build --packages-select ch2_node    # 只编译这一个包（加快迭代）
source install/setup.bash
ros2 run ch2_node ch2_node                 # 运行过程式节点
ros2 run ch2_node ch2_oop_node             # 运行 OOP 节点
ros2 run ch2_node ch2_oop_node --ros-args -p greeting:=你好    # 用参数覆盖问候语
```

**Python 版对照**：`python3 py/ch2_node.py`（ch2_node 的 rclpy 等价实现，注意它是裸脚本不是包）。

## 2.6 常见坑

1. **`colcon: command not found` 或找不到依赖**——没有 `source /opt/ros/humble/setup.bash`，这是新手最常犯的错误
2. **在 workspace 根目录而非 src/ 里创建包**——包会被 colcon 忽略或报错
3. **改了 CMakeLists.txt/package.xml 只 `ros2 run` 不重新 build**——install/ 里还是旧产物，必须重新 `colcon build`
4. **包名 ≠ 可执行文件名**——`ros2 run <包名> <可执行名>`，可执行名由 CMakeLists 的 `add_executable(xxx ...)` 决定，一个包可以有多个可执行文件（本包就有两个）
5. **spin 返回后程序立刻退出**——`rclcpp::spin` 被 Ctrl+C 打断后会继续执行后面的代码，这是正常的；节点逻辑要放在回调里而不是 spin 之后

## 2.7 练习

1. 用 `ros2 pkg create` 新建一个包，把 ch2_oop_node.cpp 复制进去改成自己的节点名和消息，完成编译运行全流程。
2. 给 OopNode 增加一个 `count_limit` 参数：计数达到上限后停止定时器（提示：`timer_->cancel()`）。
3. 同时运行 `ros2 run ch2_node ch2_node` 和 `ros2 run ch2_node ch2_oop_node`，用 `ros2 node list` 观察两个节点共存，再用 `ros2 node info /oop_node` 查看它的参数。

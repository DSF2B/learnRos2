## 7.2 三个经典问题：我在哪？要去哪？怎么去？

这是移动机器人导航的三大问题，Nav2 分别用三个组件回答：

| 问题 | 组件 | 说明 |
|------|------|------|
| 我在哪（定位） | AMCL | 粒子滤波：激光数据 + 里程计 + 地图 → 估计位姿 |
| 要去哪（规划） | Planner（全局）+ Controller（局部） | 全局规划在地图上找路径；局部控制实际走并避障 |
| 地图从哪来 | SLAM | 边建图边定位；slam_toolbox 是 ROS 2 常用实现 |

Nav2 不是单一节点，而是**一堆节点 + 行为树（Behavior Tree）**编排的框架。核心外部接口：

- **Action**：`navigate_to_pose`（前往一个目标点，就是本章用的）
- **话题**：`/amcl_pose`（当前位姿）、`/plan`（全局路径）、`/map`（地图）
- **行为树**：导航任务编排（先去 A、充电、再去 B…），树上节点可替换（ch8 的插件机制）

## 7.3 建图流程（slam_toolbox）

```bash
# 1. 启动仿真（ch6 的小车 + 一个带障碍物的世界）
ros2 launch ch6_robot gazebo.launch.py

# 2. 启动 slam_toolbox 在线建图
ros2 launch slam_toolbox online_async_launch.py

# 3. RViz2 里加 Map / LaserScan 显示，用键盘或 cmd_vel 遥控小车走遍全场
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r cmd_vel:=/diff_drive_controller/cmd_vel

# 4. 满意后保存地图（生成 map.pgm + map.yaml）
ros2 run nav2_map_server map_saver_cli -f ~/map
```

建图要点：**走慢一点、走遍每一个角落**、转弯处多停留，地图质量决定导航质量。

## 7.4 启动导航（Nav2）

```bash
# 用官方 bringup，指定地图和参数
ros2 launch nav2_bringup bringup_launch.py map:=/path/to/map.yaml
# 若仿真未开则同时启动 ch6 的 gazebo.launch.py
```

RViz2 操作三连：**2D Pose Estimate**（给初始位姿，也可以像本程序那样程序化发布 `/initialpose`）→ **2D Goal Pose**（给目标点，等于发一次 navigate_to_pose 请求）→ 观察路径与运动。小车上 TF 树是 `map → odom → base_link`，缺一环导航都不工作。

## 7.5 程序解析：patrol_navigation.cpp

巡检是工业机器人最常见的应用：**沿着固定路线循环巡逻**。用 Nav2 的 action 接口实现，代码展示三个关键技术点：

### ① 程序化初始位姿

```cpp
initial_pose_pub_ = this->create_publisher<geometry_msgs::msg::PoseWithCovarianceStamped>(
  "/initialpose", 10);
```

发布一次 `/initialpose`（map 系下坐标 + 协方差），等效于 RViz2 里点一下 2D Pose Estimate。**协方差表示不确定度**，0.25 表示"比较确定"——真机上来自部署时的固定停靠点标定。

### ② 异步 action 客户端（三回调模式）

```cpp
auto send_options = rclcpp_action::Client<NavigateToPose>::SendGoalOptions();
send_options.feedback_callback = ...;   // 导航进行中：打印剩余距离
send_options.result_callback  = ...;    // 到达/失败：去下一个航点
action_client_->async_send_goal(goal, send_options);
```

与 ch4 服务的 `async_send_request` 同构，但 action 多了 **feedback（进度反馈）**——长任务必须有反馈，否则调用方不知道任务是否还活着。反馈回调里 `distance_remaining` 每秒节流打印一次（`RCLCPP_INFO_THROTTLE` 或手动时间戳判断，本程序用后者）。

### ③ 任务状态机

结果回调里判断 `result.code`：成功 → `waypoint_index_++` 继续；失败 → 记录后继续（真实系统这里应做重试或告警上抛）。航点走完一轮后索引归零，**无限循环巡检**。

> 想发单个目标点？把航点数组改成从参数读取，或直接 `ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{pose: {...}}"`。

## 7.7 常见坑

1. **机器人原地打转/不走**——AMCL 没收到初始位姿（/initialpose 没发或发的坐标系不是 map）；或地图加载失败（map.yaml 路径错，检查 bringup 终端日志）。
2. **导航目标被拒绝**——目标点在地图外或被障碍物占据，`ros2 action send_goal` 会立刻返回失败。
3. **action 服务一直不上线**——Nav2 没启动完（bringup 要十几秒），或节点间 ROS_DOMAIN 环境不一致。
4. **TF 报 map→odom 不存在**——AMCL 没起来或没收敛；`ros2 run tf2_tools view_frames` 检查 TF 树。
5. **程序发布 initialpose 后机器人跳位**——初始位姿与真实位置差太多且协方差设得太小，AMCL 会强行相信它。协方差大=更不确定。

## 7.8 练习

1. 把航点数组改成从参数 `waypoints`（double 数组，每 3 个一组）读取，实现不重新编译即可改路线。
2. 用 `ros2 action send_goal` 手动发一个目标点，对比程序发目标的日志差异。
3. 在反馈回调里增加"失败前预警"：剩余距离 < 0.5m 时打印即将到达。
4. （进阶）订阅 `/amcl_pose`，在结果回调里计算"实际到达位置 vs 目标位置"的误差并打印。

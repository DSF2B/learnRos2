## 9.2 系统架构：上位机与下位机

真机最常见的架构是"两块脑子"：

```
┌──────────── 上位机（树莓派/工控机，跑 ROS 2）────────────┐
│ 导航 Nav2 ── cmd_vel ──► robot_driver（本章节点）         │
│  SLAM / 传感器驱动                    │                 │
└───────────────────────────────────────┼─────────────────┘
                                        │ 串口 / CAN / 网口
┌───────────────────────────────────────▼─────────────────┐
│ 下位机（STM32/ESP32 单片机）                              │
│ 电机驱动 PWM ── 编码器计数 ── IMU 读取 ── 电池检测        │
└──────────────────────────────────────────────────────────┘
```

- **上位机**：算力要求高的任务（导航、SLAM、视觉），跑完整 ROS 2
- **下位机**：实时性要求高的任务（电机控制、编码器），跑裸机/RTOS；资源受限的单片机跑不了完整 ROS 2，可用 **micro-ROS** 接入

## 9.3 下位机三件事：单片机基础

| 任务 | 技术 | 说明 |
|------|------|------|
| 点灯/电机 | GPIO/PWM | 单片机"Hello World"；PWM 占空比控制电机电压 |
| 读传感器 | ADC / I2C / 串口 | 超声波、IMU、OLED 屏的常见接口 |
| 与上位机通信 | 串口/USB-CDC | 自定义协议或 micro-ROS |

> 本书/教程配套的常见选择：ESP32（micro-ROS 官方支持）+ PlatformIO 开发环境。无硬件时先用本章仿真节点理解流程。

## 9.4 PID 调速：让轮子"听话"

开环给电机一个电压，实际转速会随负载/电压波动。**闭环 PID** 是工业控制的基石：

```
目标转速 ──►┌─ e(t) ──► P: kp·e      ┐
            │         I: ki·∫e dt    ├─► 输出 ──► 电机
实测转速 ◄──┴         D: kd·de/dt    ┘      │
       ▲                                   │
       └────────────── 编码器 ◄─────────────┘
```

三项各司其职（本程序 PidController 类的实现）：

- **P（比例）**：误差大输出大，响应快——但单独使用有稳态误差
- **I（积分）**：累积历史误差，消除稳态误差——但会引起超调/震荡，需**积分限幅**防 windup
- **D（微分）**：预测误差趋势，抑制震荡——对噪声敏感，实际工程常设为 0（PI 控制）

调参口诀：先 P 后 I 再加 D；P 增大响应变快但震荡；I 消除静差但拖慢系统。

## 9.5 差速运动学与里程计

两轮差速小车只有两个输入（左右轮速），运动学公式是底盘控制的核心（robot_driver.cpp 中 ① ② ③ 步）：

**逆解**（cmd_vel → 轮速，cmd_vel_callback）：

```
w_left  = (v - w·d/2) / r      # v 线速度，w 角速度，d 轮距，r 轮半径
w_right = (v + w·d/2) / r
```

**正解**（轮速 → 位姿增量，control_loop ③）：

```
v = (w_left + w_right) · r / 2
w = (w_right - w_left) · r / d
x += v·cos(θ)·dt;  y += v·sin(θ)·dt;  θ += w·dt
```

**轮式里程计的先天缺陷**：轮子打滑、地面不平、轮径误差都会累积，**误差随时间无界增长**。所以真机必须里程计 + IMU 融合（EKF），导航再靠 AMCL + 激光矫正。代码里 odom 协方差设 0.01 就是这个含义——它表示"我的位置数据大概有多可信"。

## 9.6 程序解析：robot_driver.cpp（仿真版底盘驱动）

本章程序是**真机驱动节点的仿真影子**：数据流与真机完全一致，只是把"真实电机"换成一阶惯性模型：

```cpp
// ② 电机模型：实际转速向指令一阶逼近（真机此步是真实电机响应）
actual_w_l_ += (cmd_l - actual_w_l_) * dt_ / tau;
```

真机移植只需改一处：把 `actual_w_` 的来源从"模型计算"换成"编码器读取"，把 PID 输出从"喂给模型"换成"写 PWM 寄存器"。其余（订阅 cmd_vel、PID、运动学、发里程计/TF）**一行不用改**——这正是分层设计的价值，也是 ch6 ros2_control 同款思路。

运行与观察：

```bash
ros2 run ch9_cpp_robot_driver robot_driver
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.3}, angular: {z: 0.5}}" --rate 10
ros2 topic echo /odom            # 位姿随时间增长
ros2 topic echo /joint_states    # 轮子转角/转速
# 调参体验：-p motor_tau:=0.8（迟钝的电机）、-p kp:=8.0（响应快但可能震荡）
```

## 9.7 micro-ROS：让单片机直接说 ROS 2 话

资源受限单片机装不下完整 ROS 2，micro-ROS 提供**精简版客户端库**（rclc），在 ESP32/STM32 上跑节点：传感器数据直接发话题、订阅 cmd_vel 直接控电机，通过串口/以太网与上位机 DDS 互联。真机流程：

1. 下位机：micro-ROS 节点读编码器 → 发 `odom`、`joint_states`；订阅 `cmd_vel` → PID → PWM
2. 上位机：跑 Nav2/建图，把下位机当作普通 ROS 节点看待
3. 联调：`ros2 topic list` 应能看到下位机发布的话题

## 9.8 常见坑

1. **里程计坐标系搞反**——odom 的 child_frame 必须与底盘 TF 的 base 一致（本程序用 base_footprint），否则 Nav2 报 TF 错。
2. **cmd_vel 没反应**——话题名不一致（ch6 的 gazebo 用 `/diff_drive_controller/cmd_vel`，本节点用 `/cmd_vel`），真机联调先 `ros2 topic info` 确认。
3. **电机正反转装反**——左右轮接线反了：现象是前进变原地打转。正解公式里左右轮速度符号取反即可验证。
4. **PID 整定崩溃**——从 P=1 开始，逐步加大到轻微震荡再退回一半，再加 I；一次调两个以上参数等于盲调。
5. **里程计跳变**——dt 计算错误或编码器溢出；定时器周期与积分 dt 必须一致（本程序两者都由 control_rate 推出）。
